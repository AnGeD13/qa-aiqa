# Чек-лист функционального тестирования "Пиццаед"

**Цель:** проверить соответствие каталога, корзины, расчёта суммы, оформления заказа и API-контракта требованиям из [`requirements.md`](../../docs/requirements.md).

**Область проверки:** UI (каталог, поиск и фильтрация, корзина, оформление заказа) и API `/api/course/v1/shop/*`. Вне области: авторизация, оплата, админ-панель, изменение статусов заказа после создания.

**Окружение:** учебный стенд «Пиццаед», актуальная версия. Все API-запросы выполняются с заголовком `X-Course-Session`, уникальным для каждого прогона. Браузер: Chrome последней версии, разрешение 1920×1080.

**Дата актуализации:** 2026-09-10

**Приоритеты:** P0 — блокирует основной путь или денежные расчёты; P1 — влияет на функциональность; P2 — детали отображения.

**Открытые вопросы:** трактовки неоднозначных требований зафиксированы в [`open-questions.md`](../../docs/open-questions.md), ссылки вида `Q-01` указывают на принятое допущение.

## CL-CAT. Каталог и карточка товара

- [ ] **P0** Каталог открывается и отображает товары всех четырёх категорий: пицца, напитки, десерты, соусы *(без каталога недоступна точка входа в основной путь)*
- [ ] **P1** Карточка товара содержит все семь полей: название, категорию, описание, цену, рейтинг, бейджи, признак наличия *(неполная карточка лишает пользователя данных для выбора)*
- [ ] **P1** Недоступный товар «Чизкейк» присутствует в каталоге и визуально помечен как отсутствующий *(требование запрещает скрывать товар, но обязывает показать статус)*
- [ ] **P0** Кнопка добавления в корзину у «Чизкейка» недоступна для нажатия *(UI-барьер против заведомо невыполнимого заказа)*
- [ ] **P2** Цена отображается в рублях в едином формате по всему каталогу *(разнобой формата снижает доверие к расчётам)*
- [ ] **P2** Рейтинг отображается в пределах допустимого диапазона, без отрицательных значений и значений выше максимума *(Q-14)*

## CL-SRCH. Поиск и фильтрация

- [ ] **P0** Поиск по названию товара возвращает соответствующие товары *(первый из трёх источников совпадения по требованию)*
- [ ] **P0** Поиск по слову из описания возвращает товары, у которых есть совпадение в описании *(второй источник совпадения)*
- [ ] **P0** Поиск по бейджу возвращает товары, у которых есть совпадение с этим бейджем *(третий источник совпадения)*
- [ ] **P0** Поиск по слову «соус» находит товары из разных категорий *(прямой критерий приёмки)*
- [ ] **P0** При активном поиске результаты отображаются по всем категориям, а не внутри выбранной ранее *(проверка приоритета поиска над фильтром, Q-12)*
- [ ] **P0** Фильтр по одной категории работает только при пустой строке поиска *(основной режим фильтрации)*
- [ ] **P1** После очистки строки поиска фильтрация по категории снова доступна *(обратный переход состояний, где чаще всего теряется работоспособность контрола)*
- [ ] **P1** Поиск не зависит от регистра введённого запроса *(Q-13)*
- [ ] **P1** Поиск по части слова возвращает совпадения *(Q-13)*
- [ ] **P1** Поиск по строке, не совпадающей ни с одним товаром, показывает пустой результат без ошибки интерфейса *(негативный сценарий, типовой источник падения верстки)*
- [ ] **P2** Запрос из одних пробелов не ломает выдачу *(некорректная обработка пустого ввода)*

## CL-CART. Корзина: состав и количество

- [ ] **P0** Доступный товар добавляется в корзину из каталога *(обязательный шаг основного пути)*
- [ ] **P0** Количество товара изменяется в пределах диапазона 1–20 *(нижняя и верхняя границы диапазона)*
- [ ] **P0** Уменьшение количества до 0 удаляет товар из корзины *(отдельное требование)*
- [ ] **P1** Корзина отображает четыре расчётных значения: сумму товаров, скидку, стоимость доставки и итоговую сумму *(пользователь должен видеть состав итоговой цены)*
- [ ] **P1** Сумма товаров равна сумме произведений цены на количество по всем позициям *(базовая арифметика, от которой зависят скидка и доставка)*
- [ ] **P1** Несколько разных товаров одновременно присутствуют в корзине как отдельные позиции *(Q-06)*
- [ ] **P1** Повторное добавление того же товара из каталога увеличивает количество существующей позиции, а не создаёт дубль
- [ ] **P1** Пустая корзина отображается корректно и не показывает мусорных значений в расчётах *(начальное состояние, часто пропускаемое при разработке)*

## CL-PROMO. Промокод и расчёт скидки

- [ ] **P0** Промокод `QA60` применяется и даёт скидку 10% от суммы товаров до доставки *(ключевое бизнес-правило)*
- [ ] **P0** Скидка округляется вниз до целых рублей на сумме, не кратной 10 *(проверяет именно округление, а не сам факт скидки)*
- [ ] **P0** Итоговая сумма равна сумме товаров минус скидка плюс доставка *(итоговая формула, которую видит пользователь)*
- [ ] **P0** Повторный ввод `QA60` не увеличивает скидку *(защита от многократного применения)*
- [ ] **P0** После изменения состава корзины скидка пересчитывается от новой суммы товаров *(скидка не должна оставаться зафиксированной старым значением)*
- [ ] **P1** Промокод с пробелами в начале и конце применяется корректно *(правило игнорирования пробелов)*
- [ ] **P1** Промокод в нижнем регистре применяется корректно *(правило нечувствительности к регистру)*
- [ ] **P1** Любой промокод, отличный от `QA60`, не даёт скидку *(Q-05)*
- [ ] **P1** Пустой промокод не даёт скидку и не вызывает ошибку интерфейса *(негативный сценарий пустого ввода)*
- [ ] **P1** При удалении всех товаров из корзины скидка обнуляется *(Q-03)*

## CL-DLV. Стоимость доставки

- [ ] **P0** При сумме товаров 1499 ₽ доставка стоит 199 ₽ *(значение непосредственно ниже порога)*
- [ ] **P0** При сумме товаров ровно 1500 ₽ доставка бесплатна *(точное значение порога, где чаще всего допускают ошибку в знаке сравнения)*
- [ ] **P0** При сумме товаров 1501 ₽ доставка бесплатна *(значение непосредственно выше порога)*
- [ ] **P0** Применение `QA60`, опускающее сумму к оплате ниже 1500 ₽, не возвращает платную доставку *(порог считается от суммы товаров до скидки, Q-01)*
- [ ] **P1** Уменьшение количества товаров ниже порога возвращает стоимость доставки 199 ₽ *(пересчёт доставки в обратном направлении)*

## CL-ORD. Оформление заказа и popup результата

- [ ] **P0** Заказ оформляется при заполненных имени, телефоне и адресе доставки *(завершающий шаг основного пути)*
- [ ] **P0** После успешного оформления отображается popup с номером заказа, суммой и статусом `created` *(прямой критерий приёмки)*
- [ ] **P0** После успешного оформления корзина становится пустой *(прямой критерий приёмки, защищает от повторного заказа)*
- [ ] **P0** Попытка оформить пустую корзину показывает popup с ошибкой *(прямой критерий приёмки)*
- [ ] **P1** Оформление с пустым именем отклоняется *(Q-08)*
- [ ] **P1** Оформление с пустым телефоном отклоняется *(Q-08)*
- [ ] **P1** Оформление с пустым адресом отклоняется *(Q-08)*
- [ ] **P1** Сумма в popup совпадает с итоговой суммой, показанной в корзине до оформления *(рассинхронизация суммы — прямой финансовый риск)*
- [ ] **P1** Заказ на минимальную сумму, например один соус, создаётся успешно *(минимальная сумма заказа не ограничена, Q-11)*
- [ ] **P1** Popup закрывается и возвращает пользователя в работоспособный интерфейс *(без этого дальнейшая работа невозможна)*

## CL-API-PROD. API: товары

- [ ] **P0** `GET /shop/products` возвращает 200 и список товаров *(базовый контракт каталога)*
- [ ] **P1** `GET /shop/products?q=соус` возвращает товары с совпадением по названию, описанию или бейджам *(серверная реализация поиска)*
- [ ] **P1** `GET /shop/products?category=` с существующей категорией возвращает товары только этой категории *(фильтрация на уровне API)*
- [ ] **P1** `GET /shop/products?in_stock=true` возвращает только доступные товары, `in_stock=false` — только недоступные *(Q-18)*
- [ ] **P1** Одновременная передача `q` и `category` обрабатывается предсказуемо *(Q-19)*
- [ ] **P1** `GET /shop/products?category=` с несуществующей категорией возвращает пустой список без ошибки сервера *(Q-18)*
- [ ] **P0** `GET /shop/products/{id}` с существующим идентификатором возвращает 200 и один товар *(контракт карточки)*
- [ ] **P0** `GET /shop/products/{id}` с несуществующим идентификатором возвращает 404 *(явно зафиксированный в требованиях код)*
- [ ] **P1** `GET /shop/products/{id}` с нечисловым идентификатором не возвращает 500 *(проверка устойчивости к некорректному типу)*

## CL-API-CART. API: корзина

- [ ] **P0** `POST /shop/cart` с доступным товаром возвращает 201 *(явно зафиксированный код)*
- [ ] **P0** `POST /shop/cart` с недоступным «Чизкейком» отклоняется *(прямой критерий приёмки, API-барьер, Q-17)*
- [ ] **P0** `GET /shop/cart` возвращает корзину текущей сессии с корректными позициями и расчётами *(источник данных для UI)*
- [ ] **P0** `PATCH /shop/cart/{productId}` изменяет количество в пределах 1–20 *(Q-15)*
- [ ] **P0** `PATCH /shop/cart/{productId}` с количеством 21 отклоняется со статусом 422 и JSON-описанием ошибки *(Q-16)*
- [ ] **P0** `PATCH /shop/cart/{productId}` с отрицательным количеством отклоняется *(Q-16)*
- [ ] **P1** `PATCH /shop/cart/{productId}` с нечисловым количеством отклоняется без ошибки сервера *(Q-16)*
- [ ] **P1** `PATCH /shop/cart/{productId}` с количеством 0 удаляет товар из корзины *(соответствие API правилу UI)*
- [ ] **P0** `DELETE /shop/cart/{productId}` удаляет товар и корзина больше не содержит эту позицию *(Q-15)*
- [ ] **P1** `DELETE /shop/cart/{productId}` для товара, отсутствующего в корзине, не возвращает 500 *(идемпотентность удаления)*
- [ ] **P1** `POST /shop/cart` для товара, уже находящегося в корзине, обрабатывается предсказуемо
- [ ] **P1** `POST /shop/cart` с количеством больше 20 отклоняется *(граница диапазона на уровне API)*

## CL-API-ORD. API: заказы

- [ ] **P0** `POST /shop/orders` с корректными данными возвращает 201 и заказ со статусом `created` *(явно зафиксированный код)*
- [ ] **P0** `POST /shop/orders` с пустой корзиной отклоняется *(критерий приёмки, продублированный на уровне API)*
- [ ] **P0** `POST /shop/orders` без обязательных полей возвращает 422 с JSON-телом ошибки *(зафиксированный формат ошибок валидации)*
- [ ] **P0** После успешного `POST /shop/orders` запрос `GET /shop/cart` возвращает пустую корзину *(критерий приёмки на уровне данных, а не только UI)*
- [ ] **P1** Сумма в ответе `POST /shop/orders` соответствует расчёту корзины с учётом скидки и доставки *(финансовая согласованность API и UI)*
- [ ] **P1** `GET /shop/orders` возвращает 200 и содержит созданный заказ *(Q-20)*

## CL-SESS. Изоляция учебных сессий

- [ ] **P0** Корзины двух разных значений `X-Course-Session` не видят друг друга *(без изоляции автотесты нестабильны при параллельном запуске)*
- [ ] **P0** Заказ, созданный в одной сессии, не появляется в списке заказов другой сессии *(та же изоляция для заказов)*
- [ ] **P1** Запрос без заголовка `X-Course-Session` обрабатывается предсказуемо и не отдаёт чужие данные *(Q-21)*

## 💡 Неочевидные проверки (граничные условия, UX, безопасность)

### Граничные условия и целостность расчётов

- [ ] **P0** Скидка на сумме товаров, дающей дробные 10%, округляется вниз, а не по правилам математического округления *(разница в 1 ₽ — это дефект расчёта, который легко пропустить)*
- [ ] **P1** Комбинация верхней границы количества и порога доставки: 20 единиц дорогого товара с применённым `QA60` рассчитывается корректно *(пересечение трёх правил одновременно)*
- [ ] **P1** Применение `QA60` до наполнения корзины, а затем добавление товаров, даёт корректную скидку *(обратный порядок действий относительно ожидаемого сценария)*
- [ ] **P1** Корзина, наполненная через API, корректно отображается в UI той же сессии *(проверка единого источника данных)*
- [ ] **P1** Изменение количества через API отражается в UI после обновления страницы *(рассинхронизация клиентского состояния и сервера)*
- [ ] **P2** Многократное быстрое нажатие кнопки увеличения количества не превышает лимит 20 *(состояние гонки на клиенте)*
- [ ] **P2** Многократное быстрое нажатие кнопки оформления заказа не создаёт несколько заказов *(дубли заказов — прямой финансовый риск)*

### UX и отображение

- [ ] **P1** Пустой результат поиска сопровождается понятным сообщением, а не просто пустой областью *(пользователь не должен принимать пустой экран за сбой)*
- [ ] **P1** Кнопка добавления недоступного товара имеет визуальное объяснение своей неактивности *(без подсказки блокировка выглядит как дефект)*
- [ ] **P2** Длинное название или описание товара не разрушает верстку карточки *(типовой дефект адаптивной сетки)*
- [ ] **P2** Каталог и корзина сохраняют работоспособность при разрешении мобильного устройства *(доставка еды заказывается преимущественно с телефона)*
- [ ] **P2** Обновление страницы не теряет содержимое корзины *(потеря корзины — частая причина отказа от заказа)*

### Безопасность и устойчивость

- [ ] **P1** Ввод HTML- и script-разметки в поле поиска не приводит к её исполнению *(базовая проверка на отражённый XSS)*
- [ ] **P1** Ввод HTML- и script-разметки в поля имени и адреса не приводит к её исполнению в popup заказа *(хранимый XSS через данные заказа)*
- [ ] **P1** Изменение цены или суммы в теле запроса `POST /shop/orders` не влияет на итоговую сумму заказа *(расчёт должен выполняться на сервере, а не приниматься от клиента)*
- [ ] **P1** Обращение к корзине с чужим значением `X-Course-Session` не позволяет изменить её содержимое *(горизонтальное повышение доступа между сессиями)*
- [ ] **P2** Сообщения об ошибках не раскрывают внутренние трассировки стека и SQL-запросы *(утечка технических деталей)*
- [ ] **P2** Очень длинная строка в поле поиска и в полях заказа не вызывает ошибку сервера *(устойчивость к переполнению ввода)*
