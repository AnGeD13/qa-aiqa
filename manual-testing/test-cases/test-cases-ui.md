# Тест-кейсы UI "Пиццаед"

**Цель:** детальная проверка каталога, поиска, корзины, расчёта скидки и доставки, оформления заказа через интерфейс.

**Область проверки:** пункты приоритетов P0 и P1 из [`checklist-pizzaed.md`](../checklists/checklist-pizzaed.md). API-кейсы вынесены в [`test-cases-api.md`](test-cases-api.md). Пункты приоритета P2 в набор не входят.

**Окружение:** учебный стенд «Пиццаед», Chrome последней версии, разрешение 1920×1080. Каждый прогон выполняется в изолированной учебной сессии.

**Дата актуализации:** 2026-09-10

**Соглашения по данным:**

- *Товар A* — любой доступный товар из категории «пицца».
- *Товар B* — любой доступный товар из категории «соусы».
- *Чизкейк* — эталонный товар не в наличии.
- Конкретные цены на стенде не зафиксированы, поэтому состав корзины для граничных сумм подбирается исполнителем и записывается в результат прогона.

## Каталог и карточка товара

### TC-CAT-01. Каталог отображает товары всех четырёх категорий

**Покрывает:** CL-CAT-1 | **Приоритет:** P0

**Предусловия:** открыта главная страница магазина, строка поиска пуста, фильтр категории не выбран.

**Шаги:**

1. Проверить наличие в каталоге товаров категории «пицца».
2. Проверить наличие товаров категории «напитки».
3. Проверить наличие товаров категории «десерты».
4. Проверить наличие товаров категории «соусы».

**Ожидаемый результат:** каталог отображает товары всех четырёх категорий, интерфейс не показывает ошибок загрузки.

**Обоснование:** каталог — единственная точка входа в основной путь пользователя. Отсутствие любой категории делает часть ассортимента недоступной для заказа.

### TC-CAT-02. Карточка товара содержит полный набор полей

**Покрывает:** CL-CAT-2 | **Приоритет:** P1

**Предусловия:** открыт каталог.

**Шаги:**

1. Найти в каталоге Товар A.
2. Проверить отображение названия.
3. Проверить отображение категории.
4. Проверить отображение описания.
5. Проверить отображение цены.
6. Проверить отображение рейтинга.
7. Проверить отображение бейджей.
8. Проверить отображение признака наличия.

**Ожидаемый результат:** все семь полей присутствуют и заполнены непустыми значениями.

**Обоснование:** требование перечисляет состав карточки явно. Неполная карточка лишает пользователя данных для выбора, а отсутствие бейджей ещё и ломает поиск по бейджам.

### TC-CAT-03. Недоступный товар отображается в каталоге с признаком отсутствия

**Покрывает:** CL-CAT-3 | **Приоритет:** P1

**Предусловия:** открыт каталог, строка поиска пуста.

**Шаги:**

1. Найти в каталоге товар «Чизкейк».
2. Проверить признак наличия в его карточке.

**Ожидаемый результат:** «Чизкейк» присутствует в каталоге и помечен как отсутствующий в наличии.

**Обоснование:** требование запрещает скрывать недоступный товар, но обязывает показать его статус. Скрытие товара — такой же дефект, как и отсутствие пометки.

### TC-CAT-04. Недоступный товар нельзя добавить в корзину из каталога

**Покрывает:** CL-CAT-4 | **Приоритет:** P0

**Предусловия:** открыт каталог, корзина пуста.

**Шаги:**

1. Найти в каталоге товар «Чизкейк».
2. Проверить состояние кнопки добавления в корзину.
3. Нажать на кнопку добавления в корзину.
4. Открыть корзину.

**Ожидаемый результат:** кнопка добавления недоступна для нажатия, «Чизкейк» в корзину не добавлен, корзина остаётся пустой.

**Обоснование:** прямой критерий приёмки. UI-барьер предотвращает заведомо невыполнимый заказ до обращения к серверу.

## Поиск и фильтрация

### TC-SRCH-01. Поиск по названию товара

**Покрывает:** CL-SRCH-1 | **Приоритет:** P0

**Предусловия:** открыт каталог, фильтр категории не выбран.

**Шаги:**

1. Зафиксировать название Товара A.
2. Ввести в строку поиска слово из названия Товара A.
3. Проверить состав выдачи.

**Ожидаемый результат:** выдача содержит Товар A.

**Обоснование:** название — первый из трёх источников совпадения, заданных требованием, и самый ожидаемый пользователем.

### TC-SRCH-02. Поиск по слову из описания

**Покрывает:** CL-SRCH-2 | **Приоритет:** P0

**Предусловия:** открыт каталог, выбран товар, у которого искомое слово присутствует в описании и отсутствует в названии.

**Шаги:**

1. Ввести в строку поиска слово, встречающееся только в описании выбранного товара.
2. Проверить состав выдачи.

**Ожидаемый результат:** выдача содержит выбранный товар.

**Обоснование:** поиск по описанию реализуется реже всего, хотя требование ставит его наравне с названием. Выбор слова, отсутствующего в названии, исключает ложноположительный результат.

### TC-SRCH-03. Поиск по бейджу

**Покрывает:** CL-SRCH-3 | **Приоритет:** P0

**Предусловия:** открыт каталог, зафиксирован бейдж существующего товара, текст которого отсутствует в его названии и описании.

**Шаги:**

1. Ввести в строку поиска текст бейджа.
2. Проверить состав выдачи.

**Ожидаемый результат:** выдача содержит товары с этим бейджем.

**Обоснование:** третий источник совпадения по требованию. Проверяется отдельно, так как бейджи часто не попадают в поисковый индекс.

### TC-SRCH-04. Поиск «соус» находит товары из разных категорий

**Покрывает:** CL-SRCH-4 | **Приоритет:** P0

**Предусловия:** открыт каталог, фильтр категории не выбран.

**Шаги:**

1. Ввести в строку поиска слово «соус».
2. Проверить категории товаров в выдаче.

**Ожидаемый результат:** выдача содержит товары более чем одной категории, если они подходят по названию, описанию или бейджам.

**Обоснование:** дословный критерий приёмки. Кейс одновременно подтверждает, что поиск не ограничен категорией с совпадающим названием.

### TC-SRCH-05. Активный поиск отменяет ограничение по выбранной категории

**Покрывает:** CL-SRCH-5, Q-12 | **Приоритет:** P0

**Предусловия:** открыт каталог, строка поиска пуста.

**Шаги:**

1. Выбрать фильтр категории «напитки».
2. Ввести в строку поиска слово «соус».
3. Проверить категории товаров в выдаче.
4. Зафиксировать состояние контрола выбора категории.

**Ожидаемый результат:** выдача содержит подходящие товары из всех категорий, а не только из «напитков». Состояние контрола фиксируется как фактическое поведение и сверяется с ответом на Q-12.

**Обоснование:** скрытая зависимость двух элементов управления. Если ограничение по категории продолжает действовать, пользователь не находит существующие товары и считает их отсутствующими.

### TC-SRCH-06. Фильтрация по категории при пустой строке поиска

**Покрывает:** CL-SRCH-6 | **Приоритет:** P0

**Предусловия:** открыт каталог, строка поиска пуста.

**Шаги:**

1. Выбрать фильтр категории «соусы».
2. Проверить категории всех товаров в выдаче.

**Ожидаемый результат:** выдача содержит только товары категории «соусы».

**Обоснование:** основной режим фильтрации, разрешённый требованием только при пустом поиске.

### TC-SRCH-07. Фильтрация восстанавливается после очистки строки поиска

**Покрывает:** CL-SRCH-7 | **Приоритет:** P1

**Предусловия:** открыт каталог.

**Шаги:**

1. Ввести в строку поиска слово «соус».
2. Полностью очистить строку поиска.
3. Выбрать фильтр категории «десерты».
4. Проверить категории товаров в выдаче.

**Ожидаемый результат:** после очистки поиска фильтр по категории снова применяется, выдача содержит только десерты.

**Обоснование:** обратный переход состояний. Контрол фильтра часто остаётся заблокированным после снятия поиска, и пользователь теряет способ навигации.

### TC-SRCH-08. Поиск не зависит от регистра и находит частичное совпадение

**Покрывает:** CL-SRCH-8, CL-SRCH-9, Q-13 | **Приоритет:** P1

**Предусловия:** открыт каталог, зафиксировано название Товара A.

**Шаги:**

1. Ввести название Товара A в верхнем регистре и проверить выдачу.
2. Ввести название Товара A в нижнем регистре и проверить выдачу.
3. Ввести первые три символа названия Товара A и проверить выдачу.

**Ожидаемый результат:** во всех трёх случаях выдача содержит Товар A.

**Обоснование:** требования не описывают правила сопоставления, а пользователи вводят запрос произвольно. Регистрозависимый или строгий поиск воспринимается как отсутствие товара.

### TC-SRCH-09. Поиск без совпадений показывает пустой результат с сообщением

**Покрывает:** CL-SRCH-10, UX-1 | **Приоритет:** P1

**Предусловия:** открыт каталог.

**Шаги:**

1. Ввести в строку поиска строку, заведомо отсутствующую в данных, например `zzzqwerty`.
2. Проверить область выдачи.

**Ожидаемый результат:** товары не отображаются, интерфейс показывает понятное сообщение об отсутствии результатов, ошибок и разрушенной верстки нет.

**Обоснование:** негативный сценарий с двойным риском: техническая ошибка при пустой выдаче и восприятие пустого экрана как сбоя приложения.

## Корзина: состав и количество

### TC-CART-01. Добавление доступного товара в корзину из каталога

**Покрывает:** CL-CART-1 | **Приоритет:** P0

**Предусловия:** открыт каталог, корзина пуста.

**Шаги:**

1. Нажать кнопку добавления в корзину у Товара A.
2. Открыть корзину.

**Ожидаемый результат:** корзина содержит одну позицию с Товаром A в количестве 1.

**Обоснование:** обязательный шаг основного пути. Без него недостижимы все последующие проверки корзины и заказа.

### TC-CART-02. Увеличение и уменьшение количества внутри диапазона

**Покрывает:** CL-CART-2 | **Приоритет:** P0

**Предусловия:** в корзине один Товар A в количестве 1.

**Шаги:**

1. Нажать кнопку увеличения количества и проверить значение.
2. Повторить увеличение до количества 5.
3. Нажать кнопку уменьшения количества и проверить значение.
4. Проверить сумму товаров после каждого изменения.

**Ожидаемый результат:** количество последовательно принимает значения 2, 5 и 4, сумма товаров пересчитывается пропорционально количеству.

**Обоснование:** базовый механизм управления количеством, от которого зависят все денежные расчёты корзины.

### TC-CART-03. Верхняя граница количества равна 20

**Покрывает:** CL-CART-3 | **Приоритет:** P0

**Предусловия:** в корзине один Товар A.

**Шаги:**

1. Увеличить количество Товара A до 20.
2. Нажать кнопку увеличения количества ещё раз.
3. Проверить количество и сумму товаров.

**Ожидаемый результат:** количество остаётся равным 20, значение 21 не достигается, сумма товаров не изменяется после лишнего нажатия.

**Обоснование:** верхняя граница диапазона, заданного требованием. Превышение лимита создаёт заказ, который магазин не обязан исполнять.

### TC-CART-04. Уменьшение количества до 0 удаляет товар из корзины

**Покрывает:** CL-CART-4 | **Приоритет:** P0

**Предусловия:** в корзине один Товар A в количестве 1.

**Шаги:**

1. Нажать кнопку уменьшения количества.
2. Проверить состав корзины.

**Ожидаемый результат:** позиция удалена, корзина пуста, расчётные значения обнулены.

**Обоснование:** требование задаёт удаление при нуле как отдельное правило. Альтернативное поведение — позиция с количеством 0 — искажает расчёты и вид корзины.

### TC-CART-05. Корзина отображает все расчётные значения и корректную сумму товаров

**Покрывает:** CL-CART-5, CL-CART-6 | **Приоритет:** P1

**Предусловия:** корзина пуста, зафиксированы цены Товара A и Товара B.

**Шаги:**

1. Добавить Товар A в количестве 2.
2. Добавить Товар B в количестве 3.
3. Проверить наличие полей: сумма товаров, скидка, стоимость доставки, итоговая сумма.
4. Вычислить ожидаемую сумму товаров как цена A × 2 + цена B × 3 и сравнить с отображаемой.

**Ожидаемый результат:** все четыре значения отображаются, сумма товаров совпадает с расчётной.

**Обоснование:** сумма товаров — база для скидки и для порога бесплатной доставки. Ошибка здесь искажает оба последующих расчёта.

### TC-CART-06. Разные товары образуют отдельные позиции

**Покрывает:** CL-CART-7 | **Приоритет:** P1

**Предусловия:** корзина пуста.

**Шаги:**

1. Добавить Товар A в корзину.
2. Добавить Товар B в корзину.
3. Проверить состав корзины.

**Ожидаемый результат:** корзина содержит две отдельные позиции, количество каждой равно 1, количеством можно управлять независимо.

**Обоснование:** объединение разных товаров в одну позицию или перезапись предыдущей — критичный дефект состава заказа.

### TC-CART-07. Повторное добавление товара увеличивает количество существующей позиции

**Покрывает:** CL-CART-8 | **Приоритет:** P1

**Предусловия:** в корзине один Товар A в количестве 1.

**Шаги:**

1. Вернуться в каталог.
2. Нажать кнопку добавления в корзину у Товара A ещё раз.
3. Проверить состав корзины.

**Ожидаемый результат:** корзина содержит одну позицию с Товаром A в количестве 2, дубль позиции не создан.

**Обоснование:** дублирование позиций ломает и отображение корзины, и логику лимита 20 единиц на товар.

### TC-CART-08. Пустая корзина отображается корректно

**Покрывает:** CL-CART-9 | **Приоритет:** P1

**Предусловия:** корзина пуста.

**Шаги:**

1. Открыть корзину.
2. Проверить состав и расчётные значения.

**Ожидаемый результат:** отображается признак пустой корзины, сумма товаров, скидка и итоговая сумма равны нулю, посторонние значения отсутствуют.

**Обоснование:** начальное состояние проверяется реже всего, при этом именно в нём проявляются ошибки инициализации расчётов, например отображение стоимости доставки для пустого заказа.

## Промокод и расчёт скидки

### TC-PROMO-01. Промокод QA60 даёт скидку 10% от суммы товаров

**Покрывает:** CL-PROMO-1 | **Приоритет:** P0

**Предусловия:** в корзине товары с суммой, кратной 10, например 1000 ₽; промокод не применён.

**Шаги:**

1. Зафиксировать сумму товаров.
2. Ввести промокод `QA60` и применить его.
3. Проверить значение скидки.

**Ожидаемый результат:** скидка равна 10% от суммы товаров, для суммы 1000 ₽ — 100 ₽.

**Обоснование:** ключевое бизнес-правило продукта и прямой критерий приёмки. Сумма выбрана кратной 10, чтобы отделить проверку процента от проверки округления.

### TC-PROMO-02. Скидка округляется вниз до целых рублей

**Покрывает:** CL-PROMO-2, EDGE-1 | **Приоритет:** P0

**Предусловия:** корзина пуста.

**Шаги:**

1. Подобрать состав корзины с суммой товаров, не кратной 10, например 1234 ₽.
2. Применить промокод `QA60`.
3. Проверить значение скидки.

**Ожидаемый результат:** скидка равна 123 ₽ — результат округления 123,4 вниз. Значения 123,4 и 124 недопустимы.

**Обоснование:** правило округления вниз задано отдельным требованием. Математическое округление или дробное отображение — дефект денежного расчёта, который не виден на «круглых» суммах.

### TC-PROMO-03. Итоговая сумма учитывает скидку и доставку

**Покрывает:** CL-PROMO-3 | **Приоритет:** P0

**Предусловия:** в корзине товары с суммой менее 1500 ₽.

**Шаги:**

1. Зафиксировать сумму товаров, скидку и стоимость доставки.
2. Применить промокод `QA60`.
3. Вычислить ожидаемый итог как сумма товаров − скидка + доставка.
4. Сравнить с отображаемой итоговой суммой.

**Ожидаемый результат:** итоговая сумма равна расчётной.

**Обоснование:** итог — единственное число, которое пользователь воспринимает как цену заказа. Ошибка порядка операций проявляется только на корзине с одновременно активной скидкой и платной доставкой.

### TC-PROMO-04. Повторное применение QA60 не увеличивает скидку

**Покрывает:** CL-PROMO-4 | **Приоритет:** P0

**Предусловия:** в корзине товары, промокод `QA60` применён, скидка зафиксирована.

**Шаги:**

1. Ввести промокод `QA60` повторно и применить его.
